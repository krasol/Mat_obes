# ADR-001: Проектирование инструмента агента

## Контекст

Для QueueManager требуется ИИ-агент, способный обрабатывать запросы пользователей
и получать информацию о талонах электронной очереди.

Агент должен использовать детерминированный инструмент, а не генерировать
информацию о талоне самостоятельно.

## Решение

Агент QueueManager реализован с использованием фреймворка CrewAI.

Агент использует следующий инструмент:

- get_ticket_status

Входные данные инструмента:
- ticket_id (формат QM-<номер>)

Выходные данные инструмента:
- status
- ticket_id
- state
- position

Провайдер LLM настраивается через переменные окружения.

## Последствия

Положительные:
- Данные о талоне поступают исключительно от инструмента.
- Выполняется проверка корректности идентификаторов талонов (ticket_id).
- Провайдера LLM можно сменить без внесения изменений в код.

Отрицательные:
- Работа агента зависит от доступности провайдера LLM.
- Для выполнения новых операций с очередью необходимо расширять набор инструментов.
